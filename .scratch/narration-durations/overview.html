The API change behind that view

GET /issues/2026-10-12/articles returns the same response version and article identity, with an optional positive integer duration_ms. Below are excerpts for the same article; all example titles and values are synthetic.

Before · legacy summary
{
  "title": "A City After Dark",
  "url": "…/a-city-after-dark",
  "audio_available": null
}
After · enriched summary
{
  "title": "A City After Dark",
  "url": "…/a-city-after-dark",
  "audio_available": true,
  "duration_ms": 1440000
}

1,440,000 milliseconds = 24 minutes. Current API serialization returns null for missing durations. Older saved summaries remain readable. Article order and table-of-contents fetch time are retained during enrichment.

Ticket 03 · planned behavior

A refreshed issue should remember its narration.

Normal issue sync fetches the table of contents. That page supplies article cards and Listen hints, not authoritative narration lengths. Ticket 03 merges saved findings by canonical article identity while refreshing ordinary article details.

Operator guide · available today

Select one saved issue, run, then browse.

Prerequisites: a working subscriber session, an existing catalog entry, and that issue’s saved article list. Missing local data fails before upstream requests; the duration command does not sync or create issues.

# If this issue is not already indexed and saved:
uv run python -m app.newyorker.archive sync
uv run python -m app.newyorker.issue sync --url https://www.newyorker.com/magazine/2026/10/12

# Run the explicit, one-issue sweep:
uv run python -m app.newyorker.durations populate --date 2026-10-12

# Read the enriched list from a running local server:
curl http://127.0.0.1:8000/issues/2026-10-12/articles
